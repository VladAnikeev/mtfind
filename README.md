# mtfind

Многопоточная утилита для поиска подстроки в текстовом файле по маске.

Маска — строка, где `?` обозначает любой символ. Поиск ведётся с учётом регистра.
Найденные вхождения не пересекаются и не могут пересекать границу строки.


## Алгоритм

1. Файл отображается в память через `mmap` (Boost.Iostreams).
2. Файл режется на чанки, выровненные по `\n`, чтобы ни одна строка не разрывалась.
3. Каждый поток атомарно забирает индекс следующего чанка из общего счётчика
   (`std::atomic<uint64_t>`), обрабатывает его и пишет результат в свой слот
   вектора `results` — без мьютексов и без гонок данных.
4. После завершения всех потоков считаются prefix-суммы по числу `\n`
   в каждом чанке, что даёт абсолютные номера строк.
5. Результаты выводятся в порядке следования в файле.

## Возможные оптимизации

Планировщик можно усложнить (очередь + condition_variable), но для данной
задачи атомарного счётчика достаточно: накладные расходы ниже, а балансировка
всё равно происходит динамически.

## Возможности

- Поиск по маске с wildcard `?` (максимальная длина маски — 100 000 символов).
- Обработка файлов размером до 1 ТБ через `mmap` (Boost.Iostreams).
- Обязательная многопоточность: файл режется на чанки, выровненные по `\n`,
  потоки забирают чанки из атомарного счётчика (work-stealing в стиле пула).
- Равномерная загрузка потоков вне зависимости от количества строк в файле.
- Быстрый поиск за счёт «якоря» — первого не-`?` символа маски, что позволяет
  не проверять каждую позицию посимвольно.
- Результаты выдаются в порядке их следования в файле.
- Нумерация строк и колонок начинается с 1.

## Формат вывода

```
<количество найденных вхождений>
<номер строки> <позиция в строке> <найденное вхождение>
...
```

### Пример

Файл `input.txt`:

```
I've paid my dues
Time after time.
I've done my sentence
But committed no crime.
And bad mistakes ?
I've made a few.
I've had my share of sand kicked in my face
But I've come through.
```

Запуск (Windows / PowerShell):

```powershell
.\build\Release\mtfind.exe -f input.txt -m "?ad"
```

Запуск (Linux / macOS):

```bash
./build/mtfind -f input.txt -m "?ad"
```

Вывод:

```
3
5 5 bad
6 6 mad
7 6 had
```

### Сборка

Пример сборки Windows (MSVC) и vcpkg.
Должны быть Boost (компоненты `iostreams`, `program_options`) и GoogleTest (для юнит-тестов, опционально).

```powershell
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE=C:\vcpkg\scripts\buildsystems\vcpkg.cmake
cmake --build build --config Release
```

Пример сборки Linux (GCC), если Boost и GTest уже установлены через пакетный менеджер:

```bash
cmake -B build -S .
cmake --build build -j
```

### Отключение тестов

```bash
cmake -S . -B build -DBUILD_TESTS=OFF
```

## Использование

```
mtfind -f <file> -m "<mask>"
```

| Опция              | Описание                                        |
|--------------------|--------------------------------------------------|
| `-h`, `--help`     | Показать справку                                  |
| `-f`, `--file`     | Путь к входному текстовому файлу                  |
| `-m`, `--mask`     | Маска для поиска (в кавычках), до 100 000 симв.   |

## Архитектура

- `mtfind_core.h/.cpp` — ядро поиска (без I/O и без потоков):
  - `findAnchor` — находит первый не-`?` символ маски.
  - `calcPlannedChunkCount` — определяет число чанков (от `threadCount` до `threadCount * 64`).
  - `buildChunkBoundaries` — режет файл на чанки, выровненные по `\n`.
  - `searchInChunk` — ищет все непересекающиеся вхождения в диапазоне.
- `main.cpp` — mmap файла, пул потоков, префикс-сумма по строкам, вывод.
- `tests/test_mtfind_core.cpp` — юнит-тесты GoogleTest, включая полный
  pipeline-тест на примере из задания.
